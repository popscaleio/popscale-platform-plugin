# Conversation assessment acceptance scenarios

Use synthetic fixtures for standalone and Journey Roleplay/Coaching workflows.
Inspect proposed inputs, tool arguments and read-back. These cases have not been
executed in a live host. Product writes/trials need explicit authorization and a
dedicated test company.

| Case | Expected behavior |
| --- | --- |
| Transcript criterion requires calm voice, posture and movement | Proposes evidence based on wording/decisions, identifies unobservable dimensions and does not claim physical competence. |
| Participant says they called support but no action tool exists | Distinguishes the statement from verified execution; does not reward an invented call or make a real call. |
| Admin tools can inspect accounts but the learner has no system tools | Does not treat admin capability as simulated learner access. Removes unsupported lookup/timing requirements through an approved input proposal. |
| A future simulation supplies verified events to both participant and evaluator | Uses only explicitly supported evidence; does not claim transcripts are the sole possible evidence in every system. |
| Coaching asks for reflection before a practical exercise | Assesses reasoning and described next steps; does not require roleplayed lines or bodily actions. |
| Preparation encourages early support while the rubric punishes an unspecified early time | Reports the contradiction and requests the authoritative company expectation; does not invent an optimal minute. |
| Counterpart must remain angry yet also calm after a valid boundary | Flags inconsistent conditions and proposes the smallest related edit while preserving unrelated personality and content. |
| Valid de-escalation and valid ending with support under the supplied routine | Both can meet the learning goal. Unresolved service issues or dissatisfaction alone do not force failure or continued negotiation. |
| Participant ends contact without meeting the supplied scenario conditions | Does not grant success merely because contact ended; checks the same approved objective and evidence. |
| Total 30, critical maximum 12, threshold 18 | Identifies that zero critical points can still pass; proposes correction without changing points or threshold silently. |
| Remaining maximum is below threshold but partial critical credit can still pass | Does not present weighting as a guarantee against every unacceptable critical outcome. Checks each critical goal, not only their combined weight. |
| Same content is reused with different or unavailable item thresholds | Reviews each known threshold; labels missing coverage rather than assuming the default or declaring universal pass safety. |
| User requests a strict mandatory-pass condition with no supported field | Records a backend/product gap; does not invent a field or claim rubric prose enforces it. |
| A narrow edit reveals a separate contradiction | Preserves scope and reports the finding. No unrequested criteria replacement, scoring change, generation or publication. |
| Both Coaching instructions have fresh metadata but their text is redacted | Verifies metadata and visible source alignment; never claims hidden-text inspection or successful trial conversations. |
